Problem Statement & Motivation

The Problem

  • Custom prosthetic sockets traditionally require plaster molding and 3D digitization — a costly, time-consuming process
  • These barriers restrict access to custom prosthetics, especially in smaller or under-resourced clinics
  • Traditional digitization equipment costs thousands of dollars
  • Process can be uncomfortable for patients

Our Solution

  • Replace expensive 3D scanning hardware with a software-only smartphone solution
  • Use the phone's camera + IMU (accelerometer & gyroscope) to generate accurate 3D scans
  • Make prosthetic fabrication faster, cheaper, and globally accessible
Broader Impact: Accessibility, affordability, and portability for global health applications

Mission Objective

Create a Mobile 3D Scanning App Capable Of:
  • Capturing synchronized camera + IMU (accelerometer + gyroscope) data
  • Reconstructing a 3D point cloud using photogrammetry (Structure from Motion)
  • Providing real-time visual feedback during scanning
  • Exporting scans to STL/OBJ formats for CAD and 3D printing

Performance Targets

  • Accuracy: ±5mm for limb scans
  • Processing Time: < 2 minutes per scan
  • Operation: Fully offline

Key Features

  • No cloud dependence
  • Real-time preview
  • Professional output formats

Algorithm Trade Study

Algorithm Purpose Pros Cons Status
COLMAP Full SfM + MVS Accurate, well-documented Heavy for mobile Primary (offline or partial)
OpenSfM Lightweight SfM Sensor integration support Python-based Backup pipeline
OpenVINS VIO (pose tracking) Robust fusion Requires NDK integration Reference only
Kimera-VIO High-accuracy VIO + mesh Rich outputs Computationally heavy Reference only
Dead Reckoning IMU tracking Native Android example Drift Used for testing
Chosen Configuration: COLMAP (SfM) + Madgwick/EKF sensor fusion for pose stabilization

Technical Trade-Offs

Key Design Decisions

On-device vs. Offline Processing

Decision: Hybrid model — scanning + light processing on phone; heavy reconstruction optional offline

Rationale: Balances performance with accessibility and privacy

Feature Algorithm Selection

Decision: ORB over SIFT/SURF

Rationale: Faster mobile execution with acceptable accuracy

Accuracy vs. Speed

Decision: Tunable resolution and iteration count

Rationale: Allows user to choose based on their needs

Hardware Independence

Decision: No LiDAR / ToF sensors — camera-only solution

Rationale: Maximizes device compatibility and keeps costs low

Test & Integration Plan

Verification Tests
  1. 3D Model Accuracy: Scan calibration cube; compare dimensions
  2. Processing Speed: Validate scan completion < 2 min
  3. Export Test: Open exported STL/OBJ in CAD software
  4. Offline Functionality: Verify complete scan with no network
Integration Plan
  • Unit test each module (Camera, IMU, SfM, UI)
  • End-to-end trial runs on Android device
  • GitHub version control for traceability
  • Regression testing after each algorithm update
Testing Facilities: Android Studio, OpenCV, COLMAP testbed

Risk Analysis

R1: Lighting Variability Causes Reconstruction Errors

Impact: Medium

Mitigation: Use preprocessing filters + user prompts for proper lighting

R2: Limited Phone CPU/GPU Resources

Impact: High

Mitigation: Optimize code, downsample images, use efficient algorithms

R3: IMU Drift During Scan

Impact: High

Mitigation: Implement periodic EKF recalibration

R4: User Motion Error

Impact: Medium

Mitigation: Real-time progress overlay + in-app tutorial

R5: API/Library Incompatibility

Impact: Medium

Mitigation: Modular interfaces + comprehensive testing
